# 任务三   工作流编排与对话状态管理

### 【任务描述】
本章旨在帮助学员从“会写 Prompt”过渡到“会搭工作流”，理解工作流（Workflow ）与 对话流（Chatflow ）的核心差异，掌握节点组件的功能定位、变量传递方式、逻辑控制流以及多轮对话中的记忆与路由机制。通过本章学习，学员将认识到：Agent 并不是一个大 Prompt，而是由输入、推理、检索、控制、记忆、输出等多个组件协同构成的执行系统。任务要求：能够说清工作流中常见节点的作用、适用场景与配置要点。能够理解变量在节点间的传递机制，并正确使用 {{variable}} 引用数据。能够区分 Workflow 与 Chatflow，理解多轮对话为什么必须引入会话状态与记忆机制。能够设计一个具备意图识别、澄清补槽、上下文记忆和条件路由能力的对话型工作流。能够搭建基础的提示词实验环境，并具备提示词版本管理意识。本章旨在帮助学员从“会写 Prompt”过渡到“会搭工作流”，理解工作流（Workflow ）与 对话流（Chatflow ）的核心差异，掌握节点组件的功能定位、变量传递方式、逻辑控制流以及多轮对话中的记忆与路由机制。通过本章学习，学员将认识到：Agent 并不是一个大 Prompt，而是由输入、推理、检索、控制、记忆、输出等多个组件协同构成的执行系统。任务要求：能够说清工作流中常见节点的作用、适用场景与配置要点。能够理解变量在节点间的传递机制，并正确使用 {{variable}} 引用数据。能够区分 Workflow 与 Chatflow，理解多轮对话为什么必须引入会话状态与记忆机制。能够设计一个具备意图识别、澄清补槽、上下文记忆和条件路由能力的对话型工作流。能够搭建基础的提示词实验环境，并具备提示词版本管理意识。
### 【任务能力目标】
能从系统编排视角理解Agent，不再把大模型当作唯一能力中心。
能围绕“节点职责清晰、变量契约明确、控制逻辑稳定”三个维度评估一个工作流设计是否合理。
能在Chatflow中配置基础记忆机制，并实现简单的意图路由与多轮澄清闭环。
### 【任务重难点】
重点；掌握节点编排、变量传递、控制流设计与对话状态管理的基本方法。
难点；从“提示词调优思维”过渡到“系统编排思维”，真正理解变量、上下文、分支和记忆在Agent中的联动关系。
### 【任务小结】
本任务的核心是帮助学员建立工作流思维：Agent 的稳定性，不只来自模型，也来自节点职责是否清晰、变量传递是否准确、控制流是否合理、记忆管理是否克制。本任务解决的问题是“Agent 如何在系统里按流程做”。学员应逐步形成这样的意识：
1. Prompt 决定单点行为，Workflow 决定系统执行。
2. 变量是工作流的数据血管，不是随手写的占位符。
3. Chatflow 的关键价值，在于把“会话状态”纳入系统设计。
4. 真正可用的 Agent，不只是答得像人，更要流得顺、接得住、记得清。
