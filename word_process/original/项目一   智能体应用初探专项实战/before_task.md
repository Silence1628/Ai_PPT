# before task

### 【情境导入】
某物流分拣中心里，每天处理上万件包裹。一件包裹从卸货到装车，要经过扫码、称重、分拣、复核——每一步都是固定的，如图 ，操作员照着屏幕提示做就行。这套流程运行了三年，稳定高效。
最近，经理想引入一个新系统：不是让人照着提示操作，而是让系统自己判断——遇到条码污损的包裹，它决定先清洁再扫码；发现疑似易碎品，它自动改走缓降滑道；甚至能根据实时车流调整分拣优先级。
请思考：
同样是自动化，二者有什么区别？
如果希望新系统在企业场景中稳定工作，新系统需要具备什么功能？如果要用你自己的话来对系统下指令实现经理的想法，需要包括哪些内容？
本任务属于智能体开发入门阶段的前置任务。通过区分工作流和智能体，让学员对目前主流的智能体构造方法以及设计思路有基础的了解，再让学员通过RAGFlow平台进行低代码开发。它的作用不是让学员直接学习提示词工程，而是先带领学员完成一个最小可运行的智能体应用，并在测试过程中建立基础评估意识，让学员看到：
只把模型接进系统，并不等于完成了智能体开发；
一个能够运行的应用，不一定已经具备稳定、专业、可控的输出能力；
当工作流先跑起来之后，许多问题会自然暴露出来，这些问题正是下一个任务“提示词工程”要重点解决的内容；
传统工作流设计如何在智能体的赋能下实现数字化转型。
