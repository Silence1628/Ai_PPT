# 任务一   上下文工程基础

### 【任务描述】
本任务旨在指导学员基于RAGFlow平台完成“智能学习助手”应用搭建，并在实践过程中理解上下文工程的核心思想。学员将围绕知识检索、对话历史管理、状态变量设计和提示词编写等关键环节，学习如何为模型动态提供恰当的信息，使其在多轮对话中能够更准确地理解需求、调用知识并生成高质量回答。通过本任务，学员将进一步认识提示词工程与上下文工程的区别与联系，掌握构建基础智能体应用的实际流程。本任务旨在指导学员基于RAGFlow平台完成“智能学习助手”应用搭建，并在实践过程中理解上下文工程的核心思想。学员将围绕知识检索、对话历史管理、状态变量设计和提示词编写等关键环节，学习如何为模型动态提供恰当的信息，使其在多轮对话中能够更准确地理解需求、调用知识并生成高质量回答。通过本任务，学员将进一步认识提示词工程与上下文工程的区别与联系，掌握构建基础智能体应用的实际流程。
### 【任务能力目标】
能理解上下文工程与提示词工程的差异及作用；
能结合任务过程观察不同上下文组织方式、检索数量、历史保留策略对模型输出效果的影响，初步形成上下文优化意识；
能根据学习辅助场景设计一个具备知识问答、学习计划生成能力的智能学习助手；
能认识到上下文工程在提升智能体稳定性、可靠性和可用性方面的现实价值，增强服务教育数字化、智能制造和产业升级场景的技术应用视野。
### 【任务重难点】
重点：掌握面向实际场景的系统提示词设计方法，以及知识检索、对话历史和状态信息的合理组织方式。
难点：理解上下文内容的增减、检索结果的取舍、历史记忆的保留方式等因素对模型回答准确性、连贯性和稳定性的影响。
### 【任务小结】
本任务系统讲解了上下文工程（Context Engineering）的核心概念、基本原则及其在智能体系统中的实际应用机制。通过对系统指令、知识检索、对话历史、记忆管理和工具定义等关键要素的分析，学员能够深入理解大模型应用为何不仅要关注“如何提问”，更要重视为模型提供什么信息、以何种方式组织信息。在实践环节，引导学员基于RAGFlow平台完成从知识库构建、工作流设计到智能学习助手搭建与优化的全过程。本任务将上下文工程的理论方法与可视化工作流开发相结合，为学员掌握智能问答应用设计、提升Agent稳定性与可用性奠定了扎实基础。

#### 一、基础知识题
1. 上下文工程（Context Engineering）的核心关注点是：A
A. 设计和管理模型在推理时所看到的全部信息
B. 只优化用户输入的提问方式
C. 只提升模型参数规模
D. 只关注知识库检索速度
2. 在上下文工程中，“渐进式披露”原则主要强调的是：A
A. 按任务阶段逐步向模型提供必要信息
B. 一次性注入所有相关资料以避免遗漏
C. 只保留系统提示词，删除其他上下文
D. 优先增加模型参数规模提高效果
3. 下列哪种做法最符合 Token 预算管理思想？D
A. 每次都检索 Top-20 文档并全部注入上下文
B. 保留全部历史对话，避免遗漏
C. 对所有用户统一使用同一套超长提示词
D. 限制检索数量，并优先保留高相关、高价值信息
4. “Lost in the Middle”现象说明：B
A. 模型最容易忽略开头的信息
B. 模型更容易忽略上下文中间位置的重要信息
C. 模型只能处理短文本
D. 模型无法使用工具定义
5. 在生产级 Agent 系统中，系统指令通常应当：C
A. 尽可能长，覆盖所有细节
B. 包含所有可能的异常情况
C. 保持简洁，定义核心角色、能力与约束
D. 完全替代知识检索和对话历史
