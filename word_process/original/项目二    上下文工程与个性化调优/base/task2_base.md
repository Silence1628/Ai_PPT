# 任务二  智能体能力调用

### 【任务描述】
本任务旨在指导学员基于 RAGFlow 平台完成“新能源汽车市场简报助手”工作流搭建任务，并在项目实践中理解工具调用、门控机制与 Agent Skill 的核心思想。学员将学习如何将大模型的语言理解能力与代码工具、文件处理能力和结构化工作流结合起来，完成从 CSV 文件上传、数据预处理、排序分析到商务简报生成的完整流程。通过本任务，学员将进一步掌握企业级智能体应用中“先判断、再调用、再生成”的设计逻辑，理解为什么稳定的输入输出接口、结构化变量约定和异常兜底机制，是智能体系统可靠运行的重要基础。本任务旨在指导学员基于 RAGFlow 平台完成“新能源汽车市场简报助手”工作流搭建任务，并在项目实践中理解工具调用、门控机制与 Agent Skill 的核心思想。学员将学习如何将大模型的语言理解能力与代码工具、文件处理能力和结构化工作流结合起来，完成从 CSV 文件上传、数据预处理、排序分析到商务简报生成的完整流程。通过本任务，学员将进一步掌握企业级智能体应用中“先判断、再调用、再生成”的设计逻辑，理解为什么稳定的输入输出接口、结构化变量约定和异常兜底机制，是智能体系统可靠运行的重要基础。
### 【任务能力目标】
能理解工具调用在智能体系统中的作用，区分平台内置工具、Function Calling 与代码节点在实际场景中的适用方式；
能认识工具调用前门控机制的重要性，避免无效调用；
能理解 Agent Skill 的概念与三层架构在复杂工作流中的实际价值；
能基于 RAGFlow 搭建一个包含文件上传、数据清洗、数据排序、结果生成与异常校验的工作流应用，并完成基础测试与优化；
能认识到结构化输入输出、变量契约和文件校验机制在企业级智能体开发中的意义，形成面向稳定性、可维护性和复用性的工程意识。
### 【任务重难点】
重点：掌握工具调用的基本流程，理解门控机制、结构化输入输出和 Skill 封装在工作流设计中的应用方法。
难点：理解为什么不能把用户输入直接连接到工具节点，以及如何通过变量契约、文件校验和异常分流机制提升智能体工作流的稳定性。
### 【任务小结】
本任务系统讲解了工具调用、门控机制与 Agent Skill 的核心概念及其在智能体工作流中的实际应用方式。通过对平台内置工具、Function Calling、结构化输入输出、条件判断和异常校验机制的介绍，学习者能够深入理解智能体为什么不能只依赖语言生成，而必须借助工具与工作流实现稳定的“理解—处理—执行—输出”闭环。在实践环节，任务引导学习者基于 RAGFlow 平台，完成了从文件上传、数据预处理、排序分析到新能源汽车市场简报生成的全过程。本任务将智能体工具调用的工程思想与低代码工作流的可视化操作结合起来，为学习者掌握面向真实业务场景的 AI 应用开发能力奠定了扎实基础。
### 【任务拓展】
#### 一、基础知识题
1. 在企业级智能体系统中，引入工具调用的主要原因是：B
A. 让模型生成更长的回答
B. 让模型具备访问外部数据和执行具体操作的能力
C. 让模型完全替代工作流节点
D. 让所有逻辑都交给自然语言处理
2. 工具调用前设置门控机制的主要作用是：C
A. 增加提示词长度
B. 提高模型随机性
C. 在执行前确认条件是否满足，降低误调用风险
D. 让工具返回更长文本
3. Agent Skill 的核心价值主要体现为：B
A. 把所有规则都写进一个 Prompt 中
B. 将某类任务相关能力封装为可复用、可组合的独立单元
C. 只用于替代 API 调用
D. 只用于多轮对话记忆
4. 在 Agent Skill 的三层架构中，负责描述 Skill 名称、场景与版本信息的是：C
A. 指令层
B. 资源层
C. 元数据层
D. 记忆层
5. 下列哪种逻辑最适合被封装为 Skill？A
A. 在多个场景中重复使用的数据清洗或结果摘要生成
B. 只在一次对话里出现且不会复用的临时描述
C. 完全依赖上一句自然语言且结构不稳定的即时任务
D. 仅靠一行简单类型转换就能完成的处理

2. 在本案例中，哪些问题必须交给 LLM 处理，哪些问题更适合交给规则和代码节点处理？请结合“简报生成、数据清洗、文件校验、排序分析、错误分流”等环节进行说明。
3. 从工程优化角度思考，本案例还可以如何改进？例如：增加文件格式校验、支持更多筛选条件、将数据清洗逻辑封装为独立 Skill，或为不同分析任务设计统一的输入输出接口。
