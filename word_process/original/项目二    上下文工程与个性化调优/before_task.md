# before task

### 【情境导入】
某制造企业希望为市场与产品部门上线一个“行业情报助手”。这个助手的目标并不复杂：每天自动获取指定行业的公开资讯，对结果进行筛选与摘要，再生成一份适合管理层阅读的简报，必要时还要发送到邮箱或企业消息渠道。
项目一开始，团队的想法很直接：既然大模型已经很强，那就给它一个Prompt，比如“请帮我整理今天的行业动态并生成报告”。但真正测试后很快发现，问题并不在于模型会不会写报告，而在于它根本拿不到实时数据，也不知道什么时候该自己回答，什么时候该调用外部能力。即便后来接入了某些工具，系统仍然会出现调用时机不对、参数生成不稳定、结果格式无法复用等问题。
团队这才意识到，企业级 Agent 的难点并不是“让模型说得更像人”，而是“让系统在正确的时候，把正确的能力和正确的信息组织给模型”。这正是上下文工程要解决的问题。
请思考：
1. 为什么一个写得不错的Prompt，仍然无法让Agent获得实时外部信息？
2. 为什么真实Agent的关键难点，不是有没有工具，而是会不会在正确时机调用工具？
3. 在一个任务里，哪些信息应该预先放进上下文，哪些信息应在执行过程中动态补充？
